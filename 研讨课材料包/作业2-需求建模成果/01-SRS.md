# 学术成果分享平台系统需求规格说明书

本说明书规定平台一期的行为、业务规则、数据与质量要求，作为模型、核心模块开发规范和验收场景的共同基线。系统面向普通用户、科研人员与平台管理员，管理论文、专利、科研项目、获奖四类学术成果。全部“应”条款表示本项目拟采纳要求；数值指标为待评审的验收目标，不表示系统已经实现或通过测试。

## 1 范围与术语

一期包括成果采集和治理、分类检索、详情、学者门户、认领与审核、本人成果维护、统计分析和合作路径解释。成果交易、收费全文下载、专利转让、社交消息不在一期。架构、数据库物理结构与云资源规格在后续设计阶段落实，不改变本说明书的业务约束。

| 术语 | 含义 |
| --- | --- |
| 学者 | 成果关联的科研人员实体，可在没有平台账号时存在 |
| 账号 | 登录及权限主体，不与来源中的作者ID等同 |
| 成果 | 四类成果之一，具有平台唯一标识，可有多条来源记录 |
| 认领 | 把账号与已有学者门户经验证和审核后建立所有者关联 |
| 规范记录 | 原始数据经校验、清洗、映射和复核后形成的可查询记录 |
| 快照 | 某一时点发布的索引或统计版本，保证分页和统计口径稳定 |
| SRS SPEC | 系统需求规格说明书与核心模块开发规范 |

课程依据为C1正文第1—4页及第8页，交付依据为C2第2—6页；来源编号定义见调研支撑材料。优先级P0为必做核心能力，P1为基础能力之后实现的必交创新项。

## 2 用户角色与权限

| 操作 | 普通用户含访客 | 登录科研人员 | 已认领科研人员 | 管理员 |
| --- | --- | --- | --- | --- |
| 检索 详情 门户 公开统计 | 允许 | 允许 | 允许 | 允许 |
| 提交本人门户认领 查看本人申请 | 需登录 | 允许 | 允许 | 按普通账号规则 |
| 修改已绑定门户展示信息 | 禁止 | 禁止 | 仅本人门户 | 治理操作需理由 |
| 修改全局成果归属 | 禁止 | 仅提交证据 | 仅提交证据 | 复核后执行 |
| 采集任务 治理 审核 审计 | 禁止 | 禁止 | 禁止 | 允许 |

管理员账号不能审核自己的认领申请；须由另一管理员处理。若演示环境仅有一名管理员，则不得以其本人认领作为通过演示，使用另一名科研人员账号。读写权限在服务端逐次校验，不能只依赖前端按钮隐藏。

## 3 业务流程与边界

数据链路：管理员登记来源与许可条件→创建采集任务→校验和清洗→成果去重与人员消歧→可靠记录入库，疑点记录隔离或送复核→发布检索版本→生成统计快照。外部数据源是系统外部参与者；限速、授权或结构变化不能被当作成功数据处理。

使用链路：访客检索并查看学者门户→科研人员登录后提交认领→系统验证材料→管理员决定通过、补充或驳回→通过后维护本人门户。用户编辑的是平台展示层与更正申请，原始来源数据保持可追溯。

## 4 功能需求

### FR01 账号与权限

系统应允许访客浏览公开信息，允许新用户注册科研人员账号并登录；写操作必须登录；后台审核、采集、治理及审计仅管理员可执行。角色由服务端校验，注册不能自授管理员角色。

优先级 P0；来源 C1；用例 UC01；规范 SP04；验收 AT01。

### FR02 采集任务管理

管理员应能选择已登记数据源、范围与批次大小，创建任务，查看进度、失败原因、重试及停止结果。系统应保留游标和任务汇总。

优先级 P0；来源 C1；用例 UC02；规范 SP01；验收 AT02。

### FR03 数据清洗

系统应保存原始字段与来源，校验必要字段，将规范化记录写入成果库；不满足必要字段的记录应进入隔离队列并提供原因。

优先级 P0；来源 C1；用例 UC02；规范 SP01；验收 AT03。

### FR04 去重与作者消歧

系统应优先使用可靠外部标识去重，对冲突标识和不确定同名记录建立人工复核任务；不得仅凭同名自动合并学者。

优先级 P0；来源 C1 D7；用例 UC03；规范 SP02；验收 AT04。

### FR05 领域分类

系统应维护有版本的领域树与来源映射；成果可关联多个领域，缺失或无法映射的记录进入未分类集合并可人工修正。

优先级 P0；来源 C1；用例 UC03；规范 SP01；验收 AT05。

### FR06 成果与学者检索

系统应提供关键词检索及类型、年份、领域、机构过滤，显示生效条件、排序方式、总量和分页；无结果时给出调整条件提示。

优先级 P0；来源 C1 E2；用例 UC04；规范 SP03；验收 AT06。

### FR07 成果详情

系统应展示成果类型、题名、关联学者、机构、年份、领域、标识、来源与更新时间，并链接至合法原始页面；未知值应明确显示。

优先级 P0；来源 C1；用例 UC05；规范 SP03；验收 AT07。

### FR08 学者门户

系统应按学者标识展示简介、研究领域及论文、专利、项目、获奖，区分公开资料聚合门户与已认证认领状态。

优先级 P0；来源 C1 E1；用例 UC06；规范 SP03；验收 AT08。

### FR09 门户认领申请

登录科研人员应能提交本人门户认领材料，查看状态和补充材料要求，或在最终决定前撤回；仅提交姓名或公开标识不足以通过。

优先级 P0；来源 C1 D7；用例 UC07；规范 SP04；验收 AT09。

### FR10 认领审核

管理员应依据身份控制证据及公开资料进行审核，记录理由；审核通过与门户所有者绑定应原子完成，确保同一门户只有一个有效所有者。

优先级 P0；来源 C1；用例 UC08；规范 SP04；验收 AT10。

### FR11 成果维护

已认领科研人员应能维护本人门户的展示信息、补录成果及提出错误归属修正；原始来源记录不得被覆盖，影响全局归属的变更须管理员复核。

优先级 P0；来源 C1；用例 UC09；规范 SP04；验收 AT11。

### FR12 统计与基础关系分析

系统应支持机构成果分类计数排名、领域关键词年度趋势与基础合著关系展示，注明口径、数据范围、缺失数据及快照时间。

优先级 P0；来源 C1；用例 UC10；规范 SP05；验收 AT12。

### FR13 合作路径解释

系统应提供按领域、机构和年份过滤的交互合作网络、最短合作路径与连边证据；该功能作为至少一项创新功能在最终验收前实现。

优先级 P1；来源 C1 E3；用例 UC11；规范 SP05；验收 AT13。

### FR14 增量更新

系统应按来源能力配置更新时间或重叠窗口游标拉取，以幂等方式处理重复数据；来源不支持增量接口时采用可重复的分批导入。

优先级 P0；来源 C1；用例 UC02；规范 SP01；验收 AT14。

### FR15 操作审计

系统应记录采集、审核、合并、修正、权限变更的操作者、时间、目标、理由及前后版本；只有管理员可以查询审计记录。

优先级 P0；来源 C1；用例 UC12；规范 SP04；验收 AT15。

### FR16 冲突处理与可追溯更正

管理员应能复核冲突证据并批准合并或拆分；系统应保存映射历史，可追踪更正的影响，按新版本重建检索和统计结果。

优先级 P0；来源 C1 D7；用例 UC03；规范 SP02；验收 AT16。

## 5 业务规则

BR01 身份独立。账号ID、平台学者ID、各来源作者ID分别保存；跨来源关联必须记录依据和状态。作者姓名不具有唯一性。

BR02 认领唯一。同一门户最多一个有效所有者；不同申请可并行等待，但最终批准必须重新检查门户所有权及申请版本。申请通过后不可再次直接审核；纠错采用管理员撤销绑定并留痕，再发起新流程。

BR03 成果归属独立。共同成果可关联多个学者。认领门户不自动验证门户内每一条成果；确认不属于本人的成果须建立更正记录。

BR04 证据优先。仅公开的姓名、机构、ORCID或论文链接不足以证明申请人为本人；验证需要账号控制证据与公开关联材料结合，管理员记录判断依据。

BR05 成果去重。相同可靠主标识且无实质冲突可以合并来源记录；不同可靠主标识不因题名相似而自动合并。预印本与期刊版可建立版本关系，但默认保留为不同成果。

BR06 统计口径。使用已发布规范成果，默认排除隔离记录，真实与模拟范围可分开查询。机构归属采用成果发生时的机构信息；缺失计入未知，不以学者当前任职补写历史。

BR07 全计数。在机构排名中，多机构成果对每个机构各计1；全站总量按成果ID去重计1。机构分项之和可能大于全站总量，应在页面说明。多领域成果在父领域聚合时去重。

BR08 修改可追溯。人工确认的更正优先于后续自动覆盖；再发生来源冲突时创建复核记录。记录前后版本、理由与操作者，不静默覆盖。

BR09 暂停和终止。运行中停止请求在批次边界生效，并通过任务版本或租约阻断迟到写入。已提交批次不自动回滚；恢复采用带父任务ID的新任务及已提交游标。

BR10 排名含义。机构排名仅表示本库给定范围内的成果数量，不用于断言学术质量；热词趋势只反映本库有效关键词记录。

## 6 数据要求

| 业务对象 | 必要信息 | 关联和约束 |
| --- | --- | --- |
| Account | 账号ID、角色、状态、认证凭据引用 | 不向普通用户暴露凭据 |
| Scholar | 学者ID、显示姓名、来源映射、认领状态 | 与Account通过所有者绑定关联 |
| Achievement | 成果ID、类型、题名、来源追踪信息 | 年份或机构缺失可为未知 |
| Authorship | 成果ID、学者ID或待消歧引用、署名顺序 | 允许多作者，不因同名强行关联 |
| Organization | 机构ID、名称、外部映射 | 历史机构归属挂在成果关联上 |
| Topic | 领域ID、父节点、名称、版本 | 成果可关联多个叶节点 |
| ClaimApplication | 申请ID、申请人、门户、状态、版本、理由 | 证据仅授权角色可见 |
| CollectionTask | 任务ID、来源、范围、状态、游标、计数、重试次数 | 原始响应和异常分开保存 |
| SourceRecord | 稳定来源记录键、内容版本哈希、抓取时刻、原始值 | 可追溯到转换规则版本 |
| ChangeRecord | 操作者、目标、前后版本、原因、发生时刻 | 支撑拆分、合并和更正回溯 |

四类成果专属字段为：论文的DOI、发表渠道；专利的国家、公开号、文献种类、发明人与申请人；项目的资助机构、批准号、负责人、依托单位；获奖的颁奖机构、奖项、年度、等级与项目编号。缺失信息不能自动补写为0、当前年份或猜测值。

时间统一按ISO 8601保存，界面按Asia/Shanghai显示；只有年份时记录精度为year，不能伪造月日。原始记录和治理历史按演示项目周期保留；认领证明在决定后30天删除正文，仅保留经最小化的审核结论及校验摘要，此为项目拟定策略，评审可调整。

## 7 外部接口与交互约束

| 交互 | 输入约束 | 输出与异常 |
| --- | --- | --- |
| 成果检索 | q最多200字符；年份上下界合法；page_size默认20 最大50 | 列表、总数、有效条件、快照与游标；非法输入返回400 |
| 学者检索 | q最多200字符；机构、年份、领域、成果类型可选 | 按学者ID分行，返回姓名、来源署名机构及年份、代表成果、认领状态和门户入口 |
| 门户查询 | platform_scholar_id | 公共资料、成果分类、认领标志；不存在返回404 |
| 认领提交 | scholar_id、证据引用、客户端幂等键 | 申请ID和状态；重复请求返回原结果或明确冲突 |
| 认领决定 | claim_id、expected_version、决定、理由 | 新状态；状态冲突返回409；禁止自审 |
| 采集任务 | 已登记来源、范围、批大小、任务幂等键 | 异步任务ID；来源不可用不得伪造成功 |
| 统计和关系 | 类型、年份、机构、领域、数据范围 | 口径说明、快照时间和结果；截断需显著提示 |

建议接口采用HTTP JSON，具体URL在接口设计阶段定稿；错误响应至少包含业务错误码、可理解信息、请求追踪ID。未认证返回401，无权限返回403；外部来源429按来源规则延迟重试，401/403立即失败并提示配置，不循环重试。

## 8 非功能需求

### NFR01 性能

在4核CPU、8GB内存的单节点验收基线及1万条成果下，索引预热后20并发、固定100条查询连续5分钟，检索API P95不超过2秒；记录实测硬件、语料、请求数和错误率。

### NFR02 数据规模

最终验收至少1万条成果，四种成果类型均有样例；真实与模拟数据逐条标记并可过滤，模拟规模不作为真实采集规模宣称。

### NFR03 权限安全

全部写接口做身份及对象权限检查；认证材料只对申请人和审核管理员可见；用越权读取、修改及并发审核场景验收。

### NFR04 数据可靠性

同一批次重复导入不增加重复成果；失败重试不重复绑定门户；服务重启后从已提交游标恢复，任务计数可核对。

### NFR05 可用性

持续30分钟演示不得出现未处理崩溃；上游不可用时展示最近已发布数据并说明更新时间，禁止返回伪造的实时成功。

### NFR06 可理解性

检索条件可见并可清除；认领页面显示当前状态和下一步；来源、数据缺失、更新时间及排名含义应在相应页面可找到。

### NFR07 更新一致性

成功提交数据后60秒内可被检索，统计快照在24小时内更新；删除或权限限制应立即阻断详情访问，索引残留不得泄露受限数据。

### NFR08 数据合规

仅接入已登记许可条件的数据源；遵守站点条款、访问限制；不采集私密联系方式、身份证件或付费论文全文，不绕过验证码。

### NFR09 可测试性

核心清洗、消歧、检索排序或统计模块中至少3个模块最终行覆盖率达到80%；测试报告记录真实结果，不把本次验收样例设计当成已通过测试。

### NFR10 工程与部署

按课程流程管理需求、代码、检查、构建、测试及部署，工具可选CodeArts或团队确定的等效方案；核心模块先有SPEC，保留AGENTS.md、提示词版本与AI修正证据。

所有性能、覆盖率和可用性数字均为验收目标。首次实测后记录环境和结果；若需修改目标，必须给出原因和版本记录，不能反向修改为“恰好通过”的数字。

## 9 验收场景

| 场景 | 需求 | 预期结果 |
| --- | --- | --- |
| AT01 | FR01 | 新用户注册后能登录且无管理员权限；重复用户名拒绝；访客读取公开成果成功，调用写接口返回401；普通账号访问审核接口返回403。 |
| AT02 | FR02 | 创建任务进入待执行；网络临时失败进入重试；最多3次重试后进入失败；运行中停止后旧工作进程不能提交新批次。 |
| AT03 | FR03 | 去除题名首尾空白并保留原始值；带空白及大写前缀的DOI规范化一致；关键词按kw-v1去重，缺失不自动生成；缺题名或类型隔离；非法日期保留原值并标记待复核。 |
| AT04 | FR04 | 规范化DOI相同的记录形成一个成果并保留两个来源；不同可靠DOI不自动合并；同名不同已验证ORCID不得合并。 |
| AT05 | FR05 | 一条成果标为两个领域；查询父领域时只计一次；无映射的成果仍可在未分类中找到。 |
| AT06 | FR06 | 组合年份与类型条件只返回交集；相同快照的游标分页无重无漏；无结果展示空状态；题名完全匹配优先；同名学者按不同ID分行，展示署名机构及年份并进入不同门户；机构过滤与成果条件联合生效。 |
| AT07 | FR07 | 详情同时显示来源链接、年份和更新时间；未知机构显示未知；页面文本中的HTML片段不得作为脚本执行。 |
