```text
│   ├── 通用材料/                # 团队、评审与 AI 使用记录
│   ├── 汇报PPT/                 # 演示文件与讲稿
│   └── 课程参考原文/            # 课程 PDF 的唯一保留位置
├── 审查记录/                    # 历史审查结论与校验依据
├── scripts/                     # 提交材料打包工具
└── dist/                        # 本地生成的提交包，Git 忽略
```

保留材料包内部的相对路径，方便 PPT 备注与文档引用定位。Markdown 源稿从现有正式 Word 的对应源文件整理而来，便于 GitHub 阅读和版本比较；Word、PPT、PDF 及模型导出图同样纳入版本管理。

## 生成提交包

使用 Python 3.10 或更新版本，无需额外安装依赖。在仓库根目录运行：

```sh
python scripts/package_materials.py
```

输出到 `dist/`：

- `01组-自定义名称8-需求调研成果.zip`
- `01组-自定义名称8-需求建模成果.zip`
- `01组-自定义名称8-研讨课完整材料.zip`
- `checksums.json`：三个包的 SHA-256、文件数量和大小。

两个作业包分别包含对应作业、通用材料、综合 PPT 和课程原文。综合 PPT 仍会引用另一作业，查阅全部来源时使用完整材料包。打包脚本只归档当前文件，不会把 Markdown 自动转换为 Word，也不会更新 PPT。

## 协作与材料状态

修改方式、提交约定和源文件同步要求见 [CONTRIBUTING.md](CONTRIBUTING.md)。

当前材料是需求草案。真实访谈、双组实验、成员人工复核、具体分工、CodeArts 建模交付与课堂反馈等事项仍需按审查报告落实；仓库初始化与文件校验不代表这些工作已完成。
